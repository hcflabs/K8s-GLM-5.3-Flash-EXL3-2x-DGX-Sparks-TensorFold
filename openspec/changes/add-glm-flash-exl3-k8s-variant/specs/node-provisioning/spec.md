# Spec: Node provisioning

## Ansible inventory

Two hosts in a `gpu` group, each with:

| Variable | Purpose | Chart mapping |
| --- | --- | --- |
| `gpu_rank` | `leader` or `worker` | `topology.rankLabels.{leader,worker}` |
| `gpu_fabric_address` | static IP on the CX7 link (with `/30`) | `topology.fabric.{masterAddr,workerAddr}` |
| `gpu_fabric_interface` | netdev name | `topology.fabric.interface` |
| `gpu_fabric_rdma_device` | RDMA device name | `topology.fabric.rdmaDevice` |
| `gpu_rank_label_key` | `node.tensorfold/rank` | `topology.rankLabels.key` |
| `gpu_models_dir` | weights root dir | parent of `weights.hostPath.*` |

## Playbook: site.yml

Runs on `hosts: gpu`, tags: `gpu_fabric`.

1. Ensure model directory exists.
2. Assert `nvidia-container-runtime` is on PATH (k3s registers the `nvidia` containerd runtime only if found at install time).
3. Write netplan config (`/etc/netplan/70-tensorfold-gpu-fabric.yaml`):
   - Static address on the CX7 link.
   - DHCP disabled, link-local disabled, MTU 9000.
   - `optional: true` so boot does not hang if the cable is disconnected.
4. Ensure `earlyoom` is absent (it reads the GPU's ~100 GB pool usage as an emergency and kills vLLM).
5. Verify the fabric:
   - The fabric interface carries its configured address.
   - The peer is reachable by ping over the fabric interface.
   - The RDMA device state is `ACTIVE`.
6. Join the existing k3s cluster as agents:
   - Roles: `k3s.orchestration.prereq`, `k3s.orchestration.k3s_agent`.
   - Labels: `nvidia.com/gpu.present=true`, `node.tensorfold/rank=<rank>`.
   - Taint: `nvidia.com/gpu=present:NoSchedule`.

## Secrets

- k3s join token: stored in `ansible/group_vars/all/vault.yml`, encrypted with
  `ansible-vault`. Written once by `init-vault.sh` (pipe `K3S_TOKEN=<token>`).
- Vault password file (`.vault_pass`): git-ignored, generated by `init-vault.sh`
  (`openssl rand -base64 48`). Never committed.
